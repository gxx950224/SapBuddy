# Harness 性能与成本评测

## 运行策略

- `contextTokens` 是用户配置的实际上下文预算（8192～2000000），优先于模型登记的 `contextWindow`；未配置时采用模型默认窗口。配置值应与所连接服务支持的窗口一致。达到预算的 80% 时由 SDK 自动压缩（在回复完成或下一次请求前检查，不截断正在生成的回复），最近上下文保留不超过预算的 1/3。单次输出上限为预算的 1/4，最多 16384 tokens；它与自动压缩阈值分别计算。
- 模型失败重试统一由 Agent 层管理，最多重试 2 次，provider 层不再叠加重试。SAP 写工具不自动重放。
- SAP 工具共用 120 秒执行截止时间，覆盖锁等待、登录、请求。取消后解锁/会话清理有独立 10 秒时限。请求已到达 SAP 时取消不代表事务回滚，必须检查最终状态。
- 源码默认 200 行；可用 `startLine` / `lineCount` 分页。超过 32000 字符的工具结果保存到 `~/.SapBuddy/output/_tool-results/`，模型获得 24000 字符预览和完整文件位置。
- 可在 `~/.SapBuddy/settings.json` 设置 `"toolProfile": "discover"`：开始只带通用工具和 `enable_sap_tools`，需要 SAP 时启用完整工具集，本会话保持启用。默认 `all` 保持既有行为。先用实际任务验证发现模式的成功率，再决定是否设为团队默认；不按关键词猜任务或擅自换模型。
- 界面上下文为估算；API 输入、输出和缓存用量来自响应。未配置非零单价的模型将费用记为未知，不把默认零单价当成免费。

## 无付费回归

```sh
npm run build
npm run bench:harness
npm run bench:web
```

Harness 回归覆盖源码分页、权限失败、超大结果、取消等待、写操作收尾、停滞网络、MCP SSE、压缩预算、上下文统计、流式顺序、工具发现、指标真实性。使用隔离夹具，不连接真实 SAP 或模型。其通过率是工程回归通过率，不等同于模型任务成功率。

## 实际任务成本

CLI/Web 每轮记录到 `~/.SapBuddy/metrics/runs.jsonl`，10 MB 轮换一次，仅保留当前和上一个文件。包含模型、工具配置、首个流事件时间、耗时、调用次数、重复次数、错误数、返回体积、Token 和 SDK 按已配置模型单价估算的费用；不保存提示、源码、工具参数或凭据。

`status: completed` 只表示生成结束。`taskSuccess` 默认 `null`；在评测副本中根据下面的验收标准补充 true/false，避免把模型自称完成算成成功。

| 固定任务 | 验收标准 |
|---|---|
| 按名称查找一个程序 | 对象、类型、当前连接正确 |
| 分析包含多个 include 的程序 | 关键入口、调用链、业务规则都有源码依据 |
| 修改并激活测试程序 | 在隔离开发系统获授权后修改正确、激活成功、无残留锁 |
| 模拟断网 | 有限时间内退出、不切换连接、不重复写入 |
| 无权限读取 | 正确识别权限问题，无同参数无限重试 |
| 大程序局部分析 | 分页读取相关内容，不漏关键逻辑、不无意加载全文 |
| 执行中取消 | 停止新请求，完成必要解锁，之后可正常发起任务 |
| 普通写作后转 SAP 查询 | 普通写作完成；切换需求时工具可发现且结果正确 |

每组使用相同任务、模型、数据与成功判据；比较 `all`/`discover` 时同时记录冷缓存与热缓存，多次运行后比较成功率、P50/P95、模型轮数、重复工具、缓存命中量、每个成功任务的总成本（含失败任务花费）。

```sh
node scripts/evaluate-harness.mjs --runs ./evaluated-runs.jsonl --compare ./baseline-runs.jsonl
```

脚本只分析已记录数据，不发起付费模型请求；没有成功判定或费用时对应指标返回 null。

## 发布门禁

```sh
npx playwright install chromium
npm run test:release
```

`test:release` 必跑浏览器测试，缺浏览器即失败。可通过 `SAPBUDDY_CHROMIUM_PATH` 使用已安装的 Chromium/Edge。GitHub Actions 在 Windows/Linux 跑相同检查，`prepublishOnly` 也执行发布门禁。开发时 `npm test` 可继续按环境跳过浏览器；发布不要使用 `--ignore-scripts` 绕过检查。
