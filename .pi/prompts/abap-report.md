# /abap-report — ABAP 报表开发与修改

## 触发条件
- 用户需要新建一个 ABAP 报表（Report）
- 用户需要修改已有 ABAP 报表的代码

## 前置阅读
- 编码规范：`SYSTEM.md`
- 代码模板与最佳实践：`.pi/skills/abap-report/SKILL.md`
- SAP 工具：直接使用内置 42 个 SAP 工具（`search_abap_objects` / `get_abap_object_lines` / `get_abap_object_info` / `replace_string_in_abap_object` / `abap_activate` 等）

## 工作流程（含确认门禁，⚠ 处必须等用户明确确认）

### 1. 理解需求
用户说了：$ARGUMENTS

从以上内容中提取已有信息：
- 操作类型：用户说了"新建/新做/创建"还是"修改/改/更新"？
- 程序名：用户是否提到了 Z/Y 开头的程序名？
- 需求细节：用户提到的表名、字段、逻辑等

**已有信息直接确认使用，只问缺失的部分**，不要重复问用户已经给过的内容。

### 2. 确认程序名
⚠ 用户确认程序名后才能继续。

### 3. 查重（决定新建/修改路径）
```
内置 `search_abap_objects` 工具（pattern=`<程序名>`）查重
```
- 不存在 → 走**新建**路径：步骤 4 → 5 → 6 → 7
- 已存在 → 走**修改**路径：步骤 4 → 5 → 6 → 7（跳过 create）

### 4. 确认表结构和现有代码
```
内置 `get_abap_object_info` 工具（TABL `<表名>`）看表结构
内置 `get_abap_object_lines` 工具（PROG `<程序名>`）读现有源码
```

### 5. 输出逻辑说明（输出契约 A）— 必须等用户确认
按以下格式汇报，⛔ 用户明确回复确认前不得做任何代码操作：
```
代码逻辑：
1. 选择屏幕：<输入字段>
2. 数据来源：<表 + 关联>
3. 处理逻辑：<汇总/计算/转换>
4. 输出格式：ALV 列表，列包括 <字段清单>
请确认是否有需要修改的地方？
```
⛔ 此步骤不可跳过。即使用户需求简单、改动少，也必须展示逻辑等确认。

### 6. 生成代码并展示 — 先展示再写文件
遵循 `SYSTEM.md` 规范生成代码（模板见 `.pi/skills/abap-report/SKILL.md`）。

⛔ 先生成代码全文展示给用户 → 用户确认 → 再写入本地文件 `output/<程序名>.abap`。
⛔ 不要先写文件后展示，不要跳过展示步骤。
⛔ 仅修改用户要求的内容，不修复程序中预先存在的 Bug（发现 Bug 时告知用户即可）。
⚠ 用户确认后才能写入 SAP。

### 7. 写入 SAP
传输请求由内置工具自动处理，无需手动指定。

新建：
```
内置 `create_object_programmatically`（PROG/I）创建空壳
内置 `replace_string_in_abap_object` 写入代码
内置 `abap_activate` 激活
```
修改：
```
内置 `replace_string_in_abap_object` 写入代码
内置 `abap_activate` 激活
```
激活报错必须修复，同步更新本地文件。同一问题连续失败 3 次 → 停手上报。

### 8. 自我检查（每次完成前必须做）
- 代码是否遵循 SYSTEM.md 的命名规范和语法规范？
- SELECT 是否指定了字段列表？（禁止 SELECT *）
- FOR ALL ENTRIES 前是否有非空检查？
- 是否在 output/ 目录生成了本地文件？
- 文件头是否有 "Generated by SapBuddy" 签名？

## 输出契约 B（完成后汇报）
新建：
```
已完成：
- 程序：<程序名>（<包名>）
- 本地文件：output/<程序名>.abap
- 功能：<一句话>
- 状态：已激活
```
修改：
```
已完成：
- 程序：<程序名>
- 本地文件：output/<程序名>.abap
- 改动：<一句话>
- 状态：已激活
```
> 修改场景不写包名，程序已有包。只有新建才填包名。
