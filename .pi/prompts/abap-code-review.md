# /abap-code-review — ABAP 代码审查

## 触发条件
- 用户说 审查/审计/code review/检查代码/看看代码问题 XXX
- **最高优先级**，覆盖其他流程规则

## 前置阅读
- 审查清单（12 维度）：.pi/skills/abap-code-review/references/checklist.md
- 审查报告 HTML 模板：.pi/skills/abap-code-review/assets/report-template.html
- 编码规范：SYSTEM.md

## 前置条件
- sap-mcp-dev MCP 服务器必须已连接，且提供 ABAP_DOWNLOAD 工具
- 若处于断开状态，停下并告知用户先连接 SAP MCP 服务器

## 工作流程（强制顺序执行）

### 1. 获取输入
用户说了：$ARGUMENTS

先看其中是否已包含程序/函数名。已有则直接使用，只问缺失的信息。

### 2. 下载源码
调用 mcp__sap-mcp-dev__ABAP_DOWNLOAD：
- **禁止先调用 `ls` 确认对象是否存在**——直接下载，对象不存在时 MCP 会返回错误
- **禁止先调用 `cat` 读取源码**——审查源码必须通过 MCP 下载
- 参数示例：{ RPROG: "X", SOPROG: "<程序名>" }（程序）或 { RFUNC: "X", SOFNAME: "<函数名>" }（函数）
- 工具返回 JSON 数组，元素为 { FILENAME: ..., CONTENT: ... }

### 3. 存档源码
将下载的源码保存到 output/ 目录，以 FILENAME 命名（如 output/ZFIR001.abap）。

### 4. 收集关联对象
留意被 INCLUDE 的程序、配置表、结构等引用对象。按程序名下载通常已包含直接 INCLUDE 的源码。

### 5. 静态走查
自顶向下逐段核对 references/checklist.md 的每一项：
- 选择屏幕 → INITIALIZATION → 主逻辑 → 输出
- 同时梳理「程序在做什么 / 怎么做」的脉络
- 若为 ALV 报表，逐字段整理取数逻辑

### 6. 问题定级
每条问题记录：id、严重度（高/中/低）、位置、现象、建议修复。
严重度配色：红=高，黄=中，蓝=低，绿=OK。

### 7. 生成 HTML 报告
将 assets/report-template.html 复制到 output/ 目录，替换每个 {{TOKEN}} 占位符为真实内容。
在报告底部/脚注添加 "Generated by AbapBuddy"。
保存为 output/<程序名>_CodeReview.html。

报告结构（4 个页签）：
1. **程序功能与结构概览**（下方嵌入「代码逻辑详细解析」+ ALV 取数表）
2. **审查发现汇总**（统计 + 汇总表）
3. **问题详解**（重点问题 / 中危问题 / 低危与改进建议）
4. **亮点与结论**（亮点 / 结论与修复优先级）

### 8. 交付结果
调用 present_files，传入 output/ 下的 HTML 报告。

## 示例（Few-Shot）

**审查发现报告格式示例：**
```
问题 #1（高）
位置：FORM f_process_data
现象：LOOP AT lt_data 前未检查内表是否为空，空表时直接进入循环虽然不会报错但浪费性能
建议：在 LOOP 前加 IF lt_data IS NOT INITIAL.

问题 #2（中）
位置：START-OF-SELECTION
现象：SELECT * FROM bkpf 使用了 SELECT *，应只取需要的字段
建议：改为 SELECT bukrs, belnr, gjahr, cpudt FROM bkpf
```

**HTML 报告结构示例（4 页签）：**
- 页签1：程序功能与结构概览 → 简述 + 逻辑解析
- 页签2：审查发现汇总 → 统计表（高/中/低数量）
- 页签3：问题详解 → 按严重度分组详细说明
- 页签4：亮点与结论 → 好的实践 + 修复优先级

已完成代码审查：
