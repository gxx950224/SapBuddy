# ABAP 程序逻辑详解（面向业务顾问）

一套可复用的程序解析流程，将 ABAP 源码翻译为业务顾问可读的逻辑说明文档。

## 何时使用

- 用户要求解释某个 ABAP 程序的业务逻辑
- 用户想知道某个程序做了什么
- 业务顾问需要理解程序的数据来源和处理流程
- 用户说详解/说明/分析一下 Z*XXX 程序

## 前置条件

- SAP 连接已配置（`get_connected_systems` 确认可用连接）。
- 源码通过**内置 SAP 工具**读取，不依赖任何 MCP 服务器。

## 执行步骤

1. **获取输入。** 从用户处确认程序/函数名称。信息不全 → 直接提问，不得假设。

2. **读取源码。** 调用内置 `get_abap_object_lines`：
   - 对象类型：报表/程序=`PROG`、函数模块=`FUNC`、类=`CLAS`。
   - 若对象名不确定，先 `search_abap_objects`（pattern=`<对象名>*`）确认存在。

3. **存档源码。** 保存到 output/ref_<程序名>.abap。

4. **解析程序结构。** 自顶向下分析源码：
   - **选择屏幕**：用户需要输入什么参数？哪些是必填？
   - **INITIALIZATION**：程序启动时做了什么初始化？
   - **START-OF-SELECTION / 主逻辑**：
     - 数据从哪些表读取？（SELECT 语句 → 表名 + 字段 + 条件）
     - 做了什么业务处理？（计算、汇总、转换、关联）
     - 输出什么？（ALV 报表 / 文件 / 接口调用）
   - **FORM 子程序**：每个 FORM 的功能是什么？

5. **输出逻辑说明。** 用业务语言（非技术术语）按以下格式输出：

`
## 程序概览
- 程序名：<程序名>
- 功能一句话：<用一句话概括程序做什么>
- 适用模块：<FI/SD/MM/CO 等>

## 业务逻辑流程
1. 用户在选择屏幕输入：<输入字段及含义>
2. 系统从 <表名> 读取 <什么数据>，筛选条件为 <条件>
3. 按 <维度> 进行 <汇总/计算/转换>
4. 关联 <表名> 获取 <补充信息>
5. 以 <输出格式> 展示：<字段清单>

## 数据来源
| 输出字段 | 来源表 | 来源字段 | 计算逻辑 |
|---------|--------|---------|---------|
| <字段>  | <表名> | <字段>  | <直接取值/SUM/计算逻辑> |

## 关键业务规则
- <规则1：如只统计未清项>
- <规则2：如按公司代码分别汇总>

## 注意事项
- <运行频率建议>
- <大数据量时的限制>
`

6. **生成 HTML 报告（可选）。** 若用户需要，生成 output/<程序名>_LogicExplanation.html，风格参考代码审查报告模板（4 页签布局）。

## 输出原则

- **用业务语言**：不说SELECT SINGLE ... INTO，说从 XX 表读取 XX 数据
- **说清楚数据流向**：输入 → 处理 → 输出，每一步都讲明白
- **字段取数逻辑表**：ALV 报表类程序必须附字段取数逻辑表
- **不遗漏关键规则**：如筛选条件、汇总维度、特殊处理逻辑
