# ABAP 程序逻辑详解（面向业务顾问）

一套可复用的程序解析流程，将 ABAP 源码翻译为业务顾问可读的逻辑说明文档。

## 何时使用

- 用户要求解释某个 ABAP 程序的业务逻辑
- 用户想知道某个程序做了什么、数据从哪来、怎么算出来的
- 业务顾问需要理解程序的处理流程
- 用户说详解/说明/分析一下 Z*XXX 程序
- ⚠️ 若用户要求"审查/检查代码质量/找 Bug"→ 走 `abap-code-review` 技能（本技能不评估代码好坏）

## 前置条件

- SAP 连接已配置（`get_connected_systems` 确认可用连接）。
- 源码通过**内置 SAP 工具**读取，不依赖任何 MCP 服务器。

## 执行步骤

### 1. 获取输入
从用户处确认程序/函数/类名称。信息不全 → 直接提问，不得假设。

### 2. 读取源码（智能分步，大程序不全量读）
- 对象类型：报表/程序=`PROG`、函数模块=`FUNC`、类=`CLAS`；对象名不确定先 `search_abap_objects`。
- **先读头部 + 事件块清单**：用 `get_abap_object_lines`（前 100 行）了解选择屏幕/事件结构，
  或用 `search_abap_object_lines` 定位 `INITIALIZATION`、`START-OF-SELECTION`、`FORM `、`PERFORM`、`CALL FUNCTION` 等关键行。
- **再按需精读关键段**（行区间读取）：主逻辑段、核心 FORM、接口调用点——避免读全量（大程序成本高）。
- 程序 > 2000 行时**必须分步读取**，禁止一次性全量拉取。

### 3. 存档源码（可选）
默认**不**在本地保存源码；仅当用户明确要求时才保存到 output/ref_<程序名>.abap。

### 4. 解析程序结构（按类型调整重点）
先判断程序类型，再对号解析：
- **报表类**（有选择屏幕 + ALV）：输入参数 → 数据读取 → 汇总/计算 → 输出字段
- **接口/批处理类**（无界面，CALL FUNCTION/提交作业）：触发方式 → 数据来源 → 处理 → 结果去向（更新哪些表/发什么消息）
- **函数模块/类**：入参 → 读取 → 业务处理 → 返回/异常

通用解析点：
- **选择屏幕**：用户输入什么？哪些必填？默认值？
- **INITIALIZATION / 启动逻辑**：做了什么初始化？
- **主逻辑**：SELECT 哪些表（表名+字段+条件）？做了什么计算/汇总/转换/关联？
- **输出**：ALV 报表 / 文件 / 接口调用 / 更新表？
- **FORM/方法**：每个子程序/方法的功能一句话

### 5. 输出逻辑说明（业务语言，结构化）

按以下格式输出（**用业务语言，不说技术术语**）：

`
## 程序概览
- 程序名：<程序名>
- 程序类型：<报表 / 接口 / 批处理 / 函数 / 类>
- 功能一句话：<用一句话概括>
- 适用模块：<FI/SD/MM/CO 等，不确定标"待确认">

## 业务逻辑流程
1. 用户输入：<输入字段及含义>（无选择屏幕则写触发方式）
2. 数据来源：从 <表名> 读取 <什么数据>，条件为 <条件>
3. 业务处理：按 <维度> 进行 <汇总/计算/转换/关联>
4. 结果输出：<输出格式 + 字段/去向>

## 数据来源（ALV 报表必填）
| 输出字段 | 来源表 | 来源字段 | 计算逻辑 |
|---------|--------|---------|---------|
| <字段>  | <表名> | <字段>  | <直接取值/SUM/公式> |

## 关键业务规则
- <规则1：如只统计未清项、按公司代码汇总、排除删除标记>
- <规则2：特殊过滤条件、日期范围、状态判断>

## 注意事项
- <运行方式：前台/后台、频率建议>
- <大数据量/性能限制>
- <与其他程序的关联：被谁调用/调用谁>

## 验证建议（帮助业务顾问核对数据）
- <如何验证结果：如用 SE16N 查某表某条件核对某字段>
- <已知口径/常见误解>
`

### 6. 追问与扩展（可选）
输出后主动提供：
- "需要我进一步解释 <某个 FORM/字段> 吗？"
- "需要我实际查一下 <某表> 的数据样例吗？"（用 `execute_data_query` 跑 3-5 行给业务顾问直观感受）
- "需要生成 HTML 版说明文档吗？"（output/<程序名>_LogicExplanation.html）

## 输出原则

- **用业务语言**：不说 `SELECT SINGLE ... INTO`，说"从 XX 表读取 XX 数据"
- **说清楚数据流向**：输入 → 处理 → 输出，每一步讲明白
- **字段取数逻辑表**：ALV 报表类必须附（输出字段 → 来源表 → 计算逻辑）
- **不遗漏关键规则**：筛选条件、汇总维度、特殊处理
- **诚实标注**：源码里没看明白/不确定的地方明确说"待确认"，不猜测
