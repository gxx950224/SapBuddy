# /abap-develop — ABAP 开发与修改（报表 / 函数模块 / 类）

## 触发条件
- 用户需要**新建或修改** ABAP 报表（Report）、函数模块（Function Module）、类（Class）
- 触发词：创建/新建/开发/修改/改 + 报表/程序/函数/类

## 前置阅读
- 编码规范：`SYSTEM.md`（默认 SAP 官方 Clean ABAP）
- 代码模板与最佳实践：`.SapBuddy/skills/abap-templates/SKILL.md`（一、报表 / 二、函数模块 / 三、类）
- SAP 工具：内置 42 个（`search_abap_objects` / `get_abap_object_lines` / `get_abap_object_info` / `create_object_programmatically` / `replace_string_in_abap_object` / `abap_activate` 等）

## 工作流程（含确认门禁，⚠ 处必须等用户明确确认）

### 1. 理解需求
用户说了：$ARGUMENTS

从以上内容中提取已有信息：
- **对象类型**：报表 / 函数模块 / 类？（未明确则问）
- **对象名**：用户是否提到了 Z/Y 开头的名称？
- **操作类型**：用户说了"新建/新做/创建"还是"修改/改/更新"？
- 需求细节：表名、字段、逻辑等

**已有信息直接确认使用，只问缺失的部分**，不要重复问用户已经给过的内容。

### 2. 确认对象名
⚠ 用户确认对象名后才能继续。

### 3. 查重（决定新建/修改路径）
```
内置 `search_abap_objects` 工具（pattern=`<对象名>*`）查重
```
- 不存在 → 走**新建**路径：步骤 4 → 5 → 6 → 7
- 已存在 → 走**修改**路径：步骤 5 → 6 → 7（跳过创建）

### 4. 新建：按对象类型创建
⚠ 创建前必须向用户展示将要创建的对象（名称/所属包），用户确认后才创建。

#### 报表（PROG）
```
内置 `create_object_programmatically`（PROG/I，name=`Z<程序名>`，package=包名）
```

#### 函数模块（FUGR）
1. 创建函数组（若不存在）：
   ```
   内置 `create_object_programmatically`（FUGR/F，name=`Z<模块>G<3位编号>`，parentName=包名）
   ```
2. 创建函数模块空壳：
   ```
   内置 `create_object_programmatically`（FUGR/FF，name=`Z<模块>_FM_<描述>`，parentName=函数组名）
   ```
3. 空壳创建后**立即定义接口参数**（IMPORTING/EXPORTING/TABLES/EXCEPTIONS）：
   - `replace_string_in_abap_object` 在 FUNCTION 语句内写入参数声明
   - 参数命名 IV_/EV_/ET_/ES_ 前缀；类型必须 DDIC 数据元素

#### 类（CLAS）
```
内置 `create_object_programmatically`（CLAS/OC，name=`ZCL_<模块>_<对象>`，package=包名）
```

### 5. 确认表结构和逻辑（输出契约 A）— 必须等用户确认
```
内置 `get_abap_object_info` 工具（TABL `<表名>`）看表结构
内置 `get_abap_object_lines` 工具（`<对象名>`）读现有源码（修改路径）
```
按以下格式汇报，⛔ 用户明确回复确认前不得做任何代码操作：
```
代码逻辑：
1. 输入：<选择屏幕/接口参数>
2. 数据来源：<表 + 关联>
3. 处理逻辑：<汇总/计算/转换>
4. 输出：<ALV 列表/返回值，字段清单>
请确认是否有需要修改的地方？
```
⛔ 此步骤不可跳过。即使用户需求简单、改动少，也必须展示逻辑等确认。

### 6. 生成代码并展示
遵循 `SYSTEM.md` 规范生成代码（模板见 `.SapBuddy/skills/abap-templates/SKILL.md` 对应章节）。

⛔ 先生成代码全文展示给用户 → 用户确认 → 才允许写入 SAP。
本地文件 `output/<对象名>.abap` **默认不生成**，仅当用户明确要求时才保存留档。
⛔ 不要先写文件后展示，不要跳过展示步骤。
⛔ 仅修改用户要求的内容，不修复程序中预先存在的 Bug（发现 Bug 时告知用户即可）。
⚠ 用户确认后才能写入 SAP。

### 7. 写入 SAP
传输请求由内置工具自动处理，无需手动指定。

新建：
```
内置 `create_object_programmatically`（空壳，见步骤 4）
内置 `replace_string_in_abap_object` 写入代码
内置 `abap_activate` 激活
```
修改：
```
内置 `replace_string_in_abap_object` 写入代码
内置 `abap_activate` 激活
```
激活报错必须修复（如生成了本地文件则同步更新）。同一问题连续失败 3 次 → 停手上报。

### 8. 自我检查（每次完成前必须做）
公共项：
- 代码是否遵循 SYSTEM.md 的命名规范和语法规范（匈牙利前缀）？
- **字段类型是否全部使用 DDIC 数据元素？（禁止裸内置类型 `TYPE i`/`char1`/`string` 等；找不到标准元素时是否创建了 Z 数据元素 + 域）**
- SELECT 是否指定了字段列表？（禁止 SELECT *）
- FOR ALL ENTRIES 前是否有非空检查？
- **代码中是否存在硬编码中文文案？（提示/错误必须走消息类或文本元素）**
- **是否已将改动内容发给用户审核并获得批准后才写入？**
- 是否按用户要求生成了本地文件（如要求）？
- 文件头是否有 "Generated by SapBuddy" 签名？

类型特例：
- 报表：ALV 字段目录显式逐字段定义；输出格式符合预期
- 函数模块：代码体在 `*"` 签名注释块之后（禁止修改接口签名）；参数名 IV_/EV_/ET_ 前缀
- 类：属性 mv_/mo_/mt_ 私有；接口解耦；异常 RAISE EXCEPTION

## 输出契约（完成后汇报）
```
已完成：
- 对象：<对象名>（类型 / 包名）
- 功能：<一句话>
- 状态：已激活
- 本地文件：<按需生成，如要求则填 output/<对象名>.abap，否则不填>
```
> 修改场景不写包名，对象已有包。只有新建才填包名。
