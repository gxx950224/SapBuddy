# FS：采购订单保存校验（增强）

状态：草稿 · 待确认 4 项 · 更新 2026-10-28
项目 / 模块：示例项目 · MM-PUR ｜ 系统与客户端：DEV / 100 ｜ 需求提出人：采购部

## 1. 需求与范围

**背景与问题**
采购订单由多人分头维护，保存时既不校验行项目交货日期与抬头凭证日期的先后，也不识别大额订单。结果有两类问题：交货日期早于凭证日期的订单进入系统，后续 MRP 交期推算出负数；超过 10 万元的订单未走高额审批，靠财务事后抽查发现。

**业务目标**
保存时拦截日期倒挂的订单；超过阈值时要求补审批标识。上线后不再新增这两类错误数据。

**在范围内**
ME21N / ME22N 的保存动作，行项目层面，公司代码 1000 与 2000。

**不在范围内**
已保存订单的历史数据修正；审批流本身（沿用既有工作流）；采购申请。

**依赖与前置条件**
审批标识的存放字段未定（Q-02）；接口创建采购订单是否同样校验未定（Q-03）。

## 2. 现状与差异

| 环节 | 系统当前行为 | 依据 |
| --- | --- | --- |
| ME21N 保存 | 不校验 EKPO-EINDT 与 EKKO-BEDAT 的先后，日期倒挂可正常保存 | E-01 |
| 大额订单 | 无金额阈值判断，也没有审批标识相关校验 | E-02 |
| 增强点候选 | 候选 BAdI `ME_PROCESS_PO_CUST` 的 CHECK 方法，尚未验证本系统是否实现及其调用时点 | E-03 |

**差异说明**：两条校验在现状中都不存在，属于新增；既有字段校验、编号分配、后续审批流保持不变。

## 3. 增强设计

### 3.1 改变的行为

| 动作 | 现状 | 目标 | 保持不变 |
| --- | --- | --- | --- |
| 保存采购订单 | 校验通过即写库 | 先执行 R-01、R-02，不通过则不写库 | 既有字段校验、订单编号分配、审批流触发 |

**实施方式**：两条都是保存前的阻断式校验，标准配置无法覆盖，走增强。CHECK 方法是否在写库前调用，待技术确认（E-03）。

### 3.2 触发点

| 入口 | 时点 | 触发前状态 | 取得的数据 |
| --- | --- | --- | --- |
| ME21N / ME22N 保存 | 抬头与行项目校验阶段，写库之前 | 订单未保存 | 用户当前输入值，含尚未落库的修改 |
| 接口 / 后台创建订单 | 待确认（Q-03） | — | — |

- **覆盖入口**：前台确定覆盖；接口与后台未确认。
- **新旧值**：使用当前输入值，不使用数据库旧值；修改行项目后重新校验。
- **未保存数据**：新增行项目的 EINDT 尚未落库，以屏幕输入为准。
- **派生值**：标准逻辑在保存时会重新计算净价与税额，不影响本规则的判断字段。

### 3.3 适用与排除

| 项目 | 定义 |
| --- | --- |
| 命中条件 | 公司代码 1000 / 2000；订单类型 NB |
| 排除条件 | 退货订单是否排除待定（Q-04）；当前按不排除处理 |
| 与其它规则的优先级 | R-01 先于 R-02；两条都不通过时先报 R-01 |
| 不命中时 | 维持原有保存行为 |
| 既有校验先失败时 | 不再执行本增强，用户先处理标准报错 |

### 3.4 处理逻辑

保存触发后，逐行项目执行 R-01；全部行通过后按整单执行 R-02。任一规则不通过即中止保存，消息中指出具体行号。变量取值、精度与舍入口径见各规则的「条件」。

### 3.5 重复触发与事务

| 场景 | 期望 |
| --- | --- |
| 同一操作多次触发 | 校验无写入副作用，可重复执行 |
| 保存后再次修改 | 重新校验全部行，不沿用上次结论 |
| 标准动作最终失败 | 本增强不产生独立数据，无需回滚 |
| 已调用外部系统 | 不适用：本增强不调用外部系统 |

### 3.6 停用与回归

- **停用后**：恢复原有保存行为；已保存数据不回滚，也不批量修复。
- **在途业务**：不适用：校验不产生在途状态。
- **回归范围**：正常保存、行项目增删改、既有字段校验、审批流创建、公司代码 1000 与 2000 之外的订单不受影响。

## 4. 业务规则

### R-01 交货日期不得早于凭证日期

- **条件**：行项目 EKPO-EINDT < 抬头 EKKO-BEDAT，按行项目逐条判断；两个字段都是日期，比较到日，不含时间。
- **结果**：阻止保存，输出 M-01，消息中带出行号。
- **异常**：任一日期为空视为未填，不参与比较，交回标准逻辑处理；两个日期相同时视为通过。
- **依据**：业务确认（2026-10-27 需求确认会），确认口径为"相等不算倒挂"。
- **验收**：T-01、T-02

### R-02 大额订单需补审批标识

- **条件**：整单金额 > 100,000.00。币种、含税口径、按整单还是行项目计算均未确定（Q-01）；当前按"整单含税人民币"计算，标【建议】。
- **结果**：输出 M-02 提示补审批标识；阻断保存或仅提示，待定（Q-01），当前按【建议：阻断】处理。
- **异常**：金额缺失或无法换算时不判断，避免把缺失当成 0；仅提示不阻断时仍记录日志。
- **依据**：业务提出阈值 10 万元，口径未确认（Q-01、Q-02）。
- **验收**：T-03、T-04

## 5. 权限、消息与运行

**权限**
沿用标准采购订单维护权限，不新增权限对象；校验对所有能保存该订单类型的用户生效，不设例外放行。

**消息**

| 编号 | 触发条件 | 用户看到的文案 |
| --- | --- | --- |
| M-01 | R-01 不通过 | 第 &1 行交货日期早于凭证日期（&2），请修改后保存 |
| M-02 | R-02 不通过 | 订单金额超过 10 万元，请补充审批标识后再保存 |

**运行**
前台保存时同步执行，单次涉及行项目通常少于 50 行；无特殊时效要求。
