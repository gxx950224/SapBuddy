# 与 grilling 集成

## 怎么加载

1. 需要追问业务决策时：读取 **`~/.SapBuddy/skills/grilling/SKILL.md`** 并按其合同执行（CLI `--skill` 与 Web 的 `agentDir` 都指向 `~/.SapBuddy/skills`；直接读文件，没有单独的技能加载工具）。用户说 grill me / 拷问 / 追问决策时同样读它，不再经别名。
2. 若读不到该文件：在对话中**按 grilling 合同**执行（设计树、按 frontier 分轮、每问带推荐答案），并在答复里说明已降级。
3. 不要把 grilling 全文复制进 FS；不要在 sap-fs 内另写一套追问算法。

## 问什么 / 不问什么

- **问**：业务决策（阈值、含税口径、是否阻断、覆盖哪些入口、排除哪些场景…）。
- **不问**：能从系统查到的事实（表名、字段、现有逻辑）——先取证。

## 与 FS 编号的映射

| grilling 结果 | 写入 FS |
| --- | --- |
| 用户确认的决定 | 落到对应 R / 第3节字段，依据写需求确认 |
| 用户说不知道 | `Q-xx`，继续做不依赖部分 |
| 推荐答案被同意 | 可写入正文；若仍弱确认可标【建议】直至正式确认 |

每轮结束后把已定决策写回草稿结构，避免只留在对话里。

## 停止条件

grilling 的 frontier 为空，且用户确认已达成共识 → 再进入生成与自检。未确认前不假装 FS 已定稿。
